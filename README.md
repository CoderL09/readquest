# ReadQuest

面向英语阅读的学习平台，把书籍阅读、意群划分、语境查词、书籍问答和间隔复习放在同一条学习流程中。

读到不理解的句子时，可以查词、追问或核对书中出处；值得保留的内容可以存为笔记或复习卡片，之后再回到原句进行回忆与迁移练习。

## 功能概览

- TXT、PDF、EPUB 和公开网页导入，书架、章节导航与阅读进度管理。
- 句子意群划分、语境查词、流式追问，以及带原文引用的书籍问答。
- 摘录笔记、生词卡和句子理解卡，配合 FSRS 调度和复习建议。
- 按书籍组织的小组讨论、成员与内容管理，以及模拟购买后的邮件激活码兑换。

## 技术设计

### 书籍 RAG 与引用定位

全书问答需要先解决两个问题：从一本书中选出与问题相关的内容，以及回答之后如何回到原文核对。检索结果和引用位置在同一条处理链路中维护，单独保存一段回答文本不足以满足后者。

章节按约 1600 字符切块，相邻块保留约 200 字符重叠，切分位置尽量落在单词边界。每个片段记录章节 ID、原文起止位置和章节内容指纹。重叠区域保留了一部分跨块语境，也会带来重复内容和额外的向量计算开销。

检索分两步：BM25 先选出最多 32 个候选，再计算问题与候选片段的 Embedding 余弦相似度，取前 3 个作为回答上下文。BM25 处理词频、逆文档频率和长度归一化，向量排序只在候选集内执行。这样限制了单次向量化和后续生成的输入规模，但语义排序无法找回词项阶段已经漏掉的片段；跨语言问题或与原文措辞差异较大的问题，仍可能检索不到合适内容。

片段向量按需生成，以模型标识和文本哈希作为缓存依据存入 MySQL，相似度在 Java 中计算。当前没有单独部署向量数据库，也没有全书向量索引；候选未命中缓存时，请求仍需等待外部向量服务。这个方案减少了部署组件，代价是检索能力和规模都受候选筛选方式约束。未配置 Embedding 时，使用词项检索结果。

生成接口同时返回回答与引用，前端按每条回答保存对应来源。打开引用时先核对章节内容指纹，再按位置高亮原文。不能只按句子文本搜索，因为同一句话可能在书中重复出现；章节修改后也应明确报告引用失效，而不是跳到另一处相似内容。

评测入口使用固定题集，包含改写问题和无答案问题，记录 Hit@3、MRR@3 与检索耗时。检索命中和回答正确是两件事，引用能够定位到原文，也不代表模型对原文的解释一定成立，因此回答依据和拒答情况需要另行核对。

### 导入任务与异常恢复

EPUB、PDF 解析涉及文件读取、内容提取和章节整理，不适合占用一次 HTTP 请求等待完成。上传接口保存源文件并返回任务 ID，后续处理交给后台工作者。任务阶段、进度和执行状态保存在 MySQL，前端按任务查询；刷新页面后仍能找回未完成的任务。同一用户上传相同文件时，SHA-256 用于查重。

任务表和章节数据放在同一个数据库，最终发布时可以在一个事务内写入章节并更新完成状态。耗时的文件解析留在事务外，事务只覆盖领取、状态更新和最终提交等数据库操作。当前采用数据库任务表，没有额外引入消息队列，任务领取和恢复的成本相应落在数据库侧。

领取任务是一条带状态条件的更新：只有排队任务或租约已过期的处理中任务可以被领取。每次执行生成新的 `run_id`，租约为 10 分钟，处理期间每 20 秒续租。进度更新、续租和最终发布都检查本次执行标识；旧工作者即使稍后返回，也不能继续提交已经被其他工作者接管的任务。

自动领取最多执行 3 次，超过上限后结束任务并记录失败原因。用户可以取消或手动重试。恢复的粒度是“重新解析已保存的源文件”，不是从解析中断处继续；源文件不必重新上传，但解析工作会重做。

### 工具调用的执行范围

复习建议需要结合阅读记录、待复习词汇和书中内容，仅靠用户的一句提问缺少这些信息。这里使用模型原生的 `tool_calls`，提供 `getReadingProgress`、`getReviewWords` 和 `searchBookPassages` 三个工具，模型按需要查询后再整理建议。

工具实现仍是普通 Java 业务方法。用户身份和书籍范围由服务端绑定，模型只提供工具声明允许的业务参数，不能传入其他 `userId` 或 `bookId` 改变查询范围。执行前检查工具名、参数字段、类型和长度，未知工具及多余身份字段会被拒绝。参数校验失败最多允许 2 次纠正。

一次运行最多交互 6 轮、调用 5 次工具，工具输出及最终回答分别限制在 16000 字符以内。另设 60 秒执行预算，在模型交互和工具执行之间检查；它是步骤间的预算判断，不等于能在第 60 秒强制打断所有外部调用。并发和会员额度也在服务端控制。

运行状态、工具事件和建议写入 MySQL，页面可以查看一次建议实际查询了哪些数据。工具集合以查询为主，生成的建议不直接写入复习计划；用户确认启动后，服务端才在事务中创建或恢复已有的到期卡片会话。生成文字、确认操作和业务写入各自有明确的入口，重复确认不会重复创建会话。

### 激活码兑换与邮件 Outbox

会员采用模拟购买。创建订单使用用户范围内的幂等键，账号和邮箱另有购买频率限制。确认模拟付款后，需要同时保留订单状态、激活码和待发送邮件任务；如果付款事务提交后再单独创建发信任务，中间的进程退出会留下已付款但没有邮件任务的订单。

因此订单更新、激活码哈希和加密的待发载荷在同一事务中保存。后台工作者领取 Outbox 任务后调用 SMTP，发送成功或失败再更新任务状态。SMTP 调用不放在数据库事务内，发信等待不会一直占着事务和记录锁。任务使用租约及执行标识，失败后退避重试，完成更新同样校验领取标识。

Outbox 解决了业务提交与发送任务之间的一致性，邮件投递仍有无法消除的窗口：SMTP 已接受邮件，而工作者尚未写回成功状态时退出，后续可能重发同一个激活码。兑换端另行校验归属、有效期与状态，以行锁、条件更新和唯一来源约束控制权益发放，所以重复邮件不会导致会员时长被重复增加。

### 意群划分与阅读上下文

意群划分涉及模型输出与原文位置的对应关系。服务端接收书籍、章节和句子 ID，重新读取原句并检查访问范围；模型给出分组后，每一组必须是原句中的子串，顺序正确，合起来完整覆盖原文。前端再校验 UTF-16 位置并保留空白。分组保存为 JSON 数组，原文中的 `/` 不参与分隔。

分析按句子触发，结果按用户和内容哈希缓存。整章自动分析会把打开书页变成一批模型请求，当前交互把这部分成本留给用户实际需要分析的句子。请求失败、额度不足或分组不合法时保留原句，已有结果可以在意群与原句之间切换。

阅读器把原文和辅助面板并排放置，点击意群、选中文字或句子按钮时，将片段及所在原句带入右侧。语境查词、句子解释直接使用阅读上下文，全书问答走 RAG；句子追问采用 SSE。选中内容变化或面板关闭时取消未完成请求，组件状态也随选中内容切换。网页与电子书共用这一套交互，窄屏则使用默认收起的面板。

### FSRS 与复习状态

生词卡保存释义、原句和书籍来源；句子理解卡可以手动填写，也可以来自追问中的候选建议。候选内容经过用户检查、编辑和确认后入库，模型输出本身不构成写入指令。

复习由服务端会话状态推进，包括词义回忆、表达解释和迁移造句。模型承担语义评估，Java 业务逻辑校验结果、决定是否推进阶段，再更新 FSRS 状态和到期时间。前端提交的是回答及操作，不接受由客户端直接指定下一次复习日期。

回答提交、阶段推进及候选确认分别处理幂等性，重复请求不应重新创建卡片或重置已有调度。卡片保留来源，回看原文时还要校验卡片归属及来源位置；查看原文不参与 FSRS 调度。

### 网页正文提取

公开链接先下载并识别内容，返回标题和摘要供用户确认，再创建导入任务。HTML 使用 Jsoup，优先取 `article`、`main`，没有对应元素时回退到页面主体；清理脚本、导航和表单，保留标题、段落、列表等结构。提取结果转为平台内的章节和句子，后面的阅读、查词、意群分析和笔记无需区分文件来源。

服务端请求外部地址需要约束访问范围。域名解析结果和每次重定向目标都要检查，限定公网 HTTP/HTTPS 地址，并限制下载大小、并发和耗时。当前不执行网页 JavaScript，正文依赖客户端渲染、需要登录或存在访问验证的页面可能无法导入；正文提取也不是完整的网站排版还原。

### 小组消息同步

小组以书籍为范围，消息和事件写入 MySQL。客户端保存事件游标，约每秒拉取后续事件，遇到积压继续拉取；切换小组时取消旧请求。成员身份和管理权限由服务端检查。

发送请求携带 `clientMessageId`，网络重试沿用同一标识，数据库侧按小组、发送者和该标识去重。客户端合并本地发送状态与服务端返回结果。当前采用 REST 事件轮询，能够沿用普通 HTTP 请求和事件游标做恢复，但会产生持续的空轮询，并带来轮询间隔内的同步延迟。

## 缓存、数据库与认证

公共书目检索接入进程内缓存和 Redis 共享缓存。正常结果的基础 TTL 为 300 秒，空结果为 20 秒，不完整结果为 15 秒，再加随机过期偏移。短期缓存空结果和不完整结果，可以减少反复请求外部书目服务，同时给暂时失败的来源保留较快恢复的机会。进程内合并相同请求，跨进程使用共享锁减少重复回源。缓存内容限于公共书目卡片，个人笔记、访问令牌和签名资源地址不放入其中。

限流由 Redis 加速，获准执行的额度记录仍持久化到 MySQL。Redis 故障时继续使用数据库判断额度，代价是数据库承担更多请求。列表筛选和分页在 SQL 中完成，关联数据批量获取，限制单页大小及最大偏移；表结构和索引由 Flyway 管理。

认证采用 Spring Security 与 JWT，刷新令牌存放在 HttpOnly Cookie 中并轮换。同一会话族内未过期的访问令牌继续有效，减少多标签页刷新令牌时互相影响；退出时撤销会话族。接口鉴权之外，书籍管理、笔记、卡片和私有资源访问还需要检查数据归属。

## 前端与构建

Vue 页面按阅读、词汇、笔记、复习和小组组织，请求、认证和错误处理集中复用。首页从阅读记录恢复章节，筛选词汇时同步调整右侧详情；这些页面状态由前端维护，导入进度和复习调度等业务状态仍以服务端为准。

前端构建产物可以合入 Java JAR，由同一个应用提供页面和 REST API。Docker 多阶段构建把 Node 和 Maven 留在构建阶段，运行镜像保留 JRE 与应用；GitHub Actions 执行前端类型、格式、测试、构建检查和后端 MySQL、Redis 集成验证。
